# Prerelease — Sealed Pool Simulator

Pick a Magic set, crack six packs, build a 40-card deck. Card data from
[Scryfall](https://scryfall.com). No backend.

## Setup

```bash
npm install
npm run dev          # http://localhost:5173
```

Put `PrereleaseSim.jsx` in `src/` alongside `main.jsx`.

## Deploy

1. Create the repo. **The repo name must match `base` in `vite.config.js`.**
   Default here assumes `prerelease-sim`.
2. Commit `package-lock.json` (generated by `npm install`) — the workflow's
   `npm ci` fails without it.
3. Repo → Settings → Pages → **Source: GitHub Actions**. Not "Deploy from a
   branch" — that's the old flow and will serve your raw source instead.
4. Push to `main`. Actions builds and publishes.

Live at `https://<user>.github.io/prerelease-sim/`.

### Blank white page after deploy?

Almost always `base`. Open devtools — if the JS bundle 404s at a path missing
the repo name, `base` is wrong. This looks like a broken app but is one line.

## Known gaps

- Wildcard slot rarity split is approximated from published aggregate rare
  rates, not official per-slot numbers.
- The List slot pulls from all of `set:plst`, not the set-specific List.
- Booster Fun variants appear in the pool but aren't separately weighted.
- Scryfall responses are cached in memory only. Scryfall asks for 24-hour
  caching — swap the `cache` ref in `PrereleaseSim.jsx` for IndexedDB if you
  use this heavily.
